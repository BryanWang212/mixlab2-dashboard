# 男装期货开发「四维」匹配看板（MVP 升级版）

> **本 SPEC 反映 MVP 完整设计**，含 4 次迭代调整：
> - v1 — 9 项 MVP 功能（基础 4 模块）
> - v2 — 引入「系列商品完成度」section
> - v3 — 双维度重构：5 系列 × 16 款 × 3 色 = 48 SKU，含 Excel 导入与中期分层锁定
> - v4 — 企划基线双维度化、分层完成图重设计、单款单色 mini-complete

---

## 1. 典型用户画像

**人物：** 王总，40岁，某中高端商务男装品牌商品企划VP。

**核心痛点：**

- **期货压货恐惧：** 订货会开完后货品不可退，最怕开发出来的货品「价不对位」（倍率不够渠道没利润，或成本太高品牌亏本）。
- **分层管理混乱：** 形象款做多了库存积压，引流款做少了渠道没量，企划部与设计部对「款量分布」口径不一致。
- **系列规划不清：** 经典商务系列该做多少款？跨系列基础款要不要做？哪些系列超量了？只看分层看不出来。
- **款 / 色混淆：** 一个款（设计概念）下有 N 个色（颜色变体），传统的款色不分导致开发进度混乱。
- **数据滞后：** 设计部交图稿很积极，但没人告诉他这些图稿对应的成本算下来，倍率是否守住了企划红线。
- **会议疲惫：** 每周看一堆Excel，但缺少一个「靶子」来集中讨论资源是投给延续款还是复购新款。
- **调整无追溯：** 中期调整分层时，谁改的、为什么改、改了哪些款？没有记录可查。

---

## 2. 场景故事（一句话描述）

> 在每两周一次的开发review会上，王总先看企划基线确认分层 × 系列双维度的规划款数，再切换到款维度总览看 16 个款的开发进度；他点击「经典西方套装」跳转单款单色分析，看到该款 3 个色都卡在「面辅料定样」节点，于是点开锁定分层弹窗，从「未锁定」改为「形象款」，调整记录自动写入导入历史；最终他据此外加倍率破红线的款式，共砍掉 3 款形象款，把资源调拨给 2 个极具潜力的复购新款。

## 3. 双维度数据模型

### 3.1 两个独立维度的关系

| 维度 | 字段 | 含义 | 取值 |
|---|---|---|---|
| **分层 (layer)** | 价格 / 角色 | 引流 / 延续 / 复购新款 / 形象款 | 4 个 |
| **系列 (series)** | 产品线 / 风格 | 经典商务 / 新商务 / 商旅 / 轻运动户外 / 跨系列基础款 | 5 个 |

两者**正交**：每个 SKU 同时属于 1 个 layer 和 1 个 series。企划规划、价格带、倍率红线各有一套；实际开发时按两个维度交叉分析（如「经典商务系列下的形象款有多少」）。

### 3.2 款 / 色双层结构

```
Style (款 — 设计概念)   ──┐
                          ├─→ SKU (单款单色 — 实际库存单位)
SKU (款 × 色变体)        ──┘
```

- **款 (Style)**：一个设计概念，如「经典行政夹克」，规划 N 个颜色变体
- **SKU**：款 × 色的组合，如「经典行政夹克 · 藏青色」= 1 个 SKU

**演示数据：** 16 款 × 3 色 = **48 SKU**

### 3.3 5 个系列 × 16 款分布

| 系列 | 款数 | 代表款 |
|---|---|---|
| **经典商务系列** | 5 | 经典行政夹克、经典锦氨裤子、经典西方套装、经典皮鞋、经典正统衬衫 |
| **新商务系列** | 4 | 现代商务衬衫、现代卡其裤、现代针织衫、现代轻商务夹克 |
| **商旅系列** | 3 | 商旅多功能外套、商旅抗皱裤、商旅羽绒夹克 |
| **轻运动户外系列** | 2 | 户外派克大衣、户外休闲T恤 |
| **跨系列基础款** | 2 | 基础白T恤、基础针织衫 |
| **总计** | **16** | |

### 3.4 双标签机制（开发初期 vs 中期）

- **开发初期**：「款色总表」Excel 一次性导入，每个 SKU 有 `series` 标签但 `actualLayer = null`、`lockedLayer = false`
- **中期**：「分层调整表」Excel 批量导入或 UI 交互式锁定 → 写入 `actualLayer` + `lockedLayer = true`
- UI 表现：未锁定款显示「⚠ 分层待定」徽章 + 「⚡ 锁定分层」按钮

## 5. MVP 交互流程设计（5 步用户操作路径）

### Step 1：期初建标（企划输入阶段）

王总在系统后台点击「新建季度企划」，上传季度企划底表。
系统锁定：4 分层规划款数 + 5 系列规划款数 + 5×4 基线矩阵 + 倍率红线 + 关键时间节点。

### Step 2：开发初期导入款色（v3 新增）

开发助理每两周（周五）上传「款色总表.xlsx」，系统自动解析为：
- 16 个 Style 记录
- 48 个 SKU 记录（款 × 色）
- 每个 SKU 自动绑定 `series` 标签 + `lockedLayer = false`

### Step 3：中期分层调整（v3 新增）

**通路 A（UI 交互）**：在款维度页点「⚡ 锁定分层」按钮 → 弹窗选 layer → 立即锁定 + 写入导入历史（带 before/after）

**通路 B（Excel 批量）**：上传「中期分层调整表.xlsx」→ 批量更新款的实际分层 → 全部 before/after 写入导入历史

### Step 4：review会前准备

王总打开看板，**先看企划基线**确认 4 分层 + 5 系列双维度的规划结构 → **切换到款维度总览**看 16 款进度 → 点击某款进入**单款单色分析**深挖 → 点击款式图打开**drawer**看成本拆解与定倍辅助。

### Step 5：会中根因分析 + 结论固化

- 在风险款手术台筛选所有倍率红灯款式
- 查看右侧抽屉的成本拆解 + 销售联动数据
- 勾选需整改款式 → 生成会议任务

## 7. 演示数据故事点

为了让看板有故事性而非冷冰冰的数字，演示数据故意埋了几个剧情：

- **形象款严重超量** — 经典西方套装 + 手工缝制西装 + 臻品羊毛西装三件套等多个高单价款式全部卡在「面辅料定样」
- **4 款大衣破倍率红线** — 经典西方套装 ¥4999/成本 920 = 5.43x（红线 6.0x）、臻品羊毛西装三件套 ¥4999/920、托斯卡纳皮衣 ¥4299/798、户外派克大衣 ¥3599/595
- **5 款未锁定分层**（演示中期调整流程） — 经典西方套装、现代轻商务夹克、商旅多功能外套、户外派克大衣、基础白T恤
- **跨系列基础款** — 基础白T恤 ¥299 + 基础针织衫 ¥499，作为流量入口和搭配款

## 8. 明确「不做什么」（MVP 边界，防范围扩大）

- 不做 自动设计 / AI 画图（只做数据匹配，不做款式生成）
- 不做 实时聊天或审批流（不替代OA系统，只做展示和导出）
- 不做 供应链端的价格比对（不连接面料B2B平台，只录入人工填写的成本）
- 不做 订货会现场下单系统（只服务于会前开发调整，不介入经销商抢单）
- 不做 **真正的 Excel 服务器端解析**（演示模式仅 toast 成功，不深度校验格式）
- 不做 **多用户协同 / 权限**（单用户演示，不区分企划/设计/销售角色）
- 不做 **历史快照对比**（仅当前状态，无 v1/v2 对比）
- 不做 **PDF 真实生成**（目前仅占位 toast，需要 html2canvas+jsPDF 真实实现）

## 9. MVP 如何实现核心意图

1. **风险前置管控** — 通过 倍率合规性扫描 + 销售折扣率联动，在样衣还没做出来前就预警「可能赔钱」的款式
2. **资源精准调配** — 通过 5 系列 × 4 分层 双维度矩阵 + 4 张分层完成图 + 16 张款卡，一眼看出哪个组合超量/不足
3. **高效会议决策** — 通过 风险款手术台，将每两周的 review 会从「念 Excel 流水账」变为「只过红灯款，表决砍/改/留」，会议时间大幅压缩
4. **调整可追溯** — 通过 改动记录 before/after 表格，中期调整的分层决策有据可查
5. **开发节奏清晰** — 通过 款 × 色 双层结构，开发部/企划部对「款进度」的口径一致
